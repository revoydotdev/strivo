# Changelog

All notable changes to strivo will be documented in this file.

Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added
- **`dev-unlock` build feature for a lead developer's own machine.**
  `cargo build --release -p strivo-bin --features creator,dev-unlock` gives an
  optimized binary that honours `STRIVO_DEV_UNLOCK_ALL=1`, which before
  worked in debug builds alone. The same override now also exposes the
  Creator surface in the web UI (`creator_enabled` in `GET
  /api/v1/settings`), which was held off in every build. Without the
  override, every build, Creator included, still reports
  `creator_enabled: false`. No published build enables the feature, and
  `scripts/check-release-version.sh` fails a release whose build files name
  it.

## [0.9.1] — 2026-10-22

### Fixed
- **Release builds fetch their bundled dependencies again.** BtbN prunes its
  ffmpeg autobuilds after about a month, so the September pin in
  `packaging/vendored-deps.toml` returned 404 and the 0.9.0 Linux and Windows
  release builds failed before publishing. ffmpeg, mpv, streamlink and yt-dlp
  are re-pinned to their 2026-10-20 builds and now download from StriVo's own
  `vendored-deps-2026-10-20` mirror release; each pin keeps its original
  source as `upstream_url`. 0.9.0 was tagged but never published, so 0.9.1 is
  the first published release with the 0.9.0 changes below.
- **A backup lists its files in the same order on every host.** The
  System page's backup rows took the archive's files in raw directory order,
  which the filesystem decides, so the same backup read `jobs.db, config.toml`
  on one machine and `config.toml, jobs.db` on another. `GET /api/v1/backups`
  now sorts each entry's file names.

### Changed
- Release jobs run on a dedicated `release` runner instead of queueing behind
  general CI.

## [0.9.0] — 2026-10-20

Everything marked **Creator Edition** below compiles only under
`--features creator`; a PVR build contains none of it (asserted by
`e2e/check-pvr-bundle.mjs`, the two-edition boot tests and `build.rs`).

### Added
- **Pull a channel's past media without subscribing to it.** The Add-Channel
  wizard's step 2 now offers three different promises: a one-off
  back-catalogue pull, a subscription, or nothing. A pull lists the channel's
  past broadcasts over the membership-agnostic routes the channel-detail pane
  already uses and queues the ticked rows through `/vods/download`, so nothing
  about the channel is persisted. A pasted YouTube `@handle` now resolves to
  its channel id through `/channels` (`forHandle`, with the legacy
  `forUsername` as a fallback rather than a parallel probe).
- **One feature-capability descriptor for both editions.**
  `crates/strivo-web/src/capabilities.rs` is the only list of what a build can
  do, what it costs, whether an executor exists and which binaries it invokes.
  `gate_pro()` takes a `CapabilityKey`, the Pro set is derived by
  `pro_slugs()`, and the capability matrix and plugin badges are projections of
  the table. `scripts/check-capability-descriptor.sh` proves the subset
  invariant with ast-grep. The descriptor route is mounted in both editions so
  "zero Pro capabilities" is an observation, not a 404.
- **Backup and restore are derivative-aware and source-link aware.** A backup
  carries a census of every project and source by id and content fingerprint.
  A restore reports Restored / Unresolved / MissingRow / IdentityMismatch per
  source and is `complete` only when every recorded source is Restored; a
  backup with no census is reported unverified rather than clean. The Creator
  database is WAL-checkpointed before it is copied. Retention draws the
  original/derivative line off the `render_plan_id` foreign key and never
  collects an output a release package still names.
- **Media proxies, waveform pyramids and bounded preview caching.** A
  1280x720 one-second-keyframe proxy, addressed by the source's sha256, is what
  the scrub reads. `src/media/spawn.rs` records every child process these
  paths start, so "no interaction path spawns an original-resolution decode"
  is asserted against what ran rather than against the code's shape.
- **A redistributable synthetic media fixture corpus** under `fixtures/media/`
  (eight classes, 702 KB, every file generated by ffmpeg from a lavfi source)
  with a verifier that re-probes the bytes rather than trusting the manifest.
  Deliberately outside `crates/strivo-web/assets/`, which is embedded into
  every binary.
- **Build-time and CI gates.** `build.rs` fails on a duplicated, skipped or
  malformed SPA module sequence number. `scripts/check-client-routes.sh`
  matches every SPA API call against a mounted route per edition.
  `scripts/check-no-blocking-command.sh` (ast-grep) proves no
  `std::process::Command` reaches a Tokio worker thread.
  `scripts/check-css-tokens.mjs` fails on a consumed-but-undefined design
  token and `scripts/check-design-tokens.mjs` on a reducible hardcoded colour.
  `scripts/measure_bundle.sh` and `scripts/check-bundle-size.sh` measure the
  served bundle off the wire and fail on more than 5% drift against
  `docs/PERFORMANCE.md`. `scripts/gen-settings-coverage.sh --check` generates
  `docs/SETTINGS-COVERAGE.md` from `SETTINGS_KEYS` so a hand edit fails the
  build. `scripts/bench_library.sh`, `bench_jobs_db.sh`, `bench_media_pool.sh`
  and `check_durable_archive.sh` form a reproducible performance harness with
  a captured baseline in `docs/perf/`. The e2e lane runs `@axe-core/playwright`
  as an enforcing WCAG 2.2 AA scan over every route in both editions.
- **Creator Edition: canonical project schema and a persistent workspace.**
  Eleven Creator-owned types (Project, SourceAsset, CaptureSession,
  TranscriptRevision, CompositionRevision, Variant, RenderPlan, Artifact,
  ReleasePackage, Publication, MetricObservation) get durable identity in the
  research database with numbered forward migrations and an explicit down per
  step. A path is a resolvable locator, never an identity. One workspace row
  per project holds the single selected revision, playhead, selection, active
  view and unsaved draft that every view reads
  (`GET /api/v1/creator/projects/{id}/workspace`). A PVR install creates no
  Creator database at all.
- **Creator Edition: the canonical time model.** `MediaTime` (whole
  microseconds, non-negative by construction) replaces the three units that
  could not see each other (`duration_ms` columns, the f32 `Cut`, the f32
  `time_sec`). `IntervalMap` maps composition time to source and back with
  integer arithmetic and refuses an unanswerable coordinate rather than
  clamping it; `ClockMap` is a list of capture parts carrying accumulated
  drift, so a reconnect hole is a gap and not a constant offset. Schema v2
  migrates `duration_ms` to `duration_us`.
- **Creator Edition: one render plan.** `strivo-editor::render` compiles a
  composition revision to a `CompiledPlan` that preview and export both
  consume; `GET .../render/plan` previews it without spawning anything.
  Insert FX, pitch/time, the caption style and the sub-mix bus, four settings
  the UI said were baked but nothing read, now reach the artifact. The dead
  second render path (`ConcatPlan` and its argv builders) is deleted.
- **Creator Edition: a frame-accurate multi-track timeline with
  browser-native preview.** Trim, split, ripple, slip, snap and lane-link post
  an edit intent and draw the compiled plan the server returns; an edit against
  a superseded revision is a 409. Every operation has both a pointer gesture
  and a key, and both post the same intent. Preview capability is tri-state so
  "not probed yet" never collapses into "cannot decode". Mediabunny, AntV X6
  and wavesurfer.js are vendored under `assets/vendor/` with `PROVENANCE.md`
  (version, SHA-256, licence), load by dynamic `import()` after first paint,
  and are removed from a PVR build by `build.rs`; `mime_for()` now serves
  `.mjs` as JavaScript.
- **Creator Edition: audio mixer, layered B-roll, destination reframing,
  brand assets and revisioned captions.** Mute, solo, gain, pan, routing,
  ducking, cleanup, fades and normalisation arrive as fields of the one
  `RenderRequest`, so preview and render cannot disagree. B-roll is placed as
  an overlay over continuing source audio rather than spliced into the cut
  list. `AspectRatio` is a parsed enum and streamer layouts (regions with
  roles) fill the render request, so a 9:16 draft renders at 9:16. Brand sets
  are authored once in a reference frame and projected per destination; a
  missing or unreviewed asset is a named refusal before any ffmpeg runs.
  Caption cues carry a `Timed` coordinate resolved through the interval map,
  so a cut moves them and a speed change shortens them.
- **Creator Edition: undo, autosave, revision branching and conflict
  detection** as one append-only history table with a parent pointer; one undo
  crosses transcript, timeline and inspector edits. Transcript editing is
  linked to composition operations without touching media: deleting a word
  range strikes the text and the source time together, and a text correction
  cannot change the picture even in principle.
- **Creator Edition: import.** Local files and folders join the same project
  collection as captured streams, keyed on content fingerprint so a moved file
  stays the same asset and a re-import reports itself as a duplicate.
  OBS-style multitrack recordings are identified per track (role plus exact
  timebase) and aligned through a `ClockMap`; a presentation-time jump is
  reported as a gap with a measured keyframe distance. An ingest readiness
  checklist reports probe, proxies, waveform, filmstrip and thumbnail per
  step, with `NotApplicable` as a state rather than a failure.
- **Creator Edition: durable creator jobs and artifacts.** `creator_jobs` and
  its append-only `creator_job_transitions` log are written in one
  transaction; `recover_jobs` re-queues what a crash froze; cache keys hash the
  declared inputs, never a file's size or mtime.
- **Creator Edition: pipelines you can author.** The Pipelines page renders the
  real executor model (`src/pipeline/stage.rs`) as a node graph, one node per
  `Stage` and one edge per `inputs` link, with `mapping_mismatches` shipped in
  the payload. Graphs are created, edited, validated and saved as templates:
  the executor's six rules now return every violation under a stable id naming
  the offending stage, edge or lock, and a seventh rule refuses a dispatch
  naming a plugin this build does not register at save time rather than hours
  later at dispatch. A submitted graph is executed verbatim with its
  `PipelineId` preserved from graph to run to history.
- **Creator Edition: live clipping during capture.** A clip may only be cut
  from finished capture segments: `LiveCapture` is fed by the recorder on the
  one path where a writer exits, and a range reaching into an open part is a
  typed `PartStillOpen` rather than a silent prefix. `render_live_clip` admits
  against the byte reserve before spawning anything, so acquisition is never
  starved; the PVR recorder-slot gate is asserted verbatim by a test.
- **Creator Edition: immutable release packages and a truthful publication
  state machine.** Fourteen states and 46 edges, enumerated in code and proven
  complete by driving all 196 ordered pairs. Editing an approved package
  revokes the approval in the same transaction; a package with any posting past
  the point of no return is locked by the store, not by convention.
  `unknown_remote_state` has no edge back to `uploading`, because re-posting a
  request whose response was lost is the duplicate-posting bug. The
  `creator_publish` template's display name is now "Ultimate creator
  preparation", since it ends at a local artifact.
- **Creator Edition: research kernel additions.** Stream events and viewer
  samples persist with coverage as a fraction, a denominator and a list of gap
  reasons. Source ownership, licence and participant-consent notes derive
  publication eligibility, and an undecided axis blocks rather than permits.
  Chat is acquired and replayed durably by the daemon (`TwitchIrc` supervised
  by `ChatCapture`; collections, messages, removals and gaps as recorded
  intervals) instead of living in a browser tab's JS array. The chat engine
  has no route and nothing starts it yet.

### Changed
- **Licence entitlement is a verified decision.** `Licence::is_entitled` no
  longer trusts two editable fields of a cache file. It verifies an ES256
  signature over a token naming this machine, issuer, tier and expiry, with
  typed refusals so "expired" (renewable) is distinguishable from "not signed
  for us" (never renewable). Cache reconnection is behind
  `[licence] cache_reconnection`, off by default, and does not re-enable
  activation, trial or purchase.
- **Pipeline runnability is reported from the executor's capability
  registry.** `GET /api/v1/pipelines/dag` no longer hardcodes
  `status: "available"` on every node. A node is runnable iff every capability
  it produces resolves to a registered provider, and the unresolved ones are
  named in `missing`. No first-party plugin had ever overridden
  `Plugin::capabilities()`, so the registry's capability index was permanently
  empty; `ArtifactPlugin` and `CrunchrPlugin` now declare the tags their
  `execute_stage` arms implement, and `strivo_plugins::register_all` is the
  single registration list for daemon and routes.
- **The pipeline run view is patched per SSE event** instead of refetching
  the whole run history three times per stage transition. The refetch was also
  wrong: `API._fetch`'s 2 s GET cache replaced the live transition with a
  stale list, so the view sat at 1/10 while the daemon was at 10/10.
- **All edit representations unified under one project revision.** The `edls`
  head table was a byte-identical copy of the newest `revisions` row and is
  dropped; "current" is a definition rather than a second stored thing. A
  Scene names a revision id instead of embedding an EDL. A stored document
  whose `recording_id` disagrees with the request path is refused by every
  reader, not only by the restore path.
- **Design tokens and accessibility.** 48 PVR call sites consumed
  `var(--text)`, a token this design system never defined (JellySkin's name
  for `--fg`), and `021-pvr.css` named ten Jellyfin variables we do not have,
  so those elements were inheriting colour rather than being set. All now
  resolve to defined tokens; the inert `data-theme="dark"` attribute is gone.
  Sub-12px text is lifted to `var(--text-xs)` and the 1x2 split-screen
  letterbox geometry is fixed; the ux-budget checks are enforcing with no
  env-var escape.
- **Dependencies.** rand 0.8 -> 0.9 (strivo-web auth ported to the new API),
  tokio-tungstenite 0.24 -> 0.30, libloading 0.8 -> 0.9, which 7 -> 8, and
  minor bumps of tokio, uuid, hyper and rust-embed. GitHub Actions pinned to
  checkout 7.0.1, setup-node 7.0.0, upload-artifact 7.0.2, download-artifact
  8.0.2, buildx 4.4.1, build-push 7.4.0 and action-gh-release 3.0.3. The
  marketing site moves to Next 16.3.6.

### Removed
- **`crunchr::SearchMode` and the empty `semantic-search` feature.** The type
  had zero consumers and every semantic branch was permanently unreachable.
- **`PRO_PLUGINS` and `CHAT_PRO_PLUGINS`**, the hand-kept Pro lists, replaced
  by the capability descriptor.

### Fixed
- **Editing a multiview layout in the composer destroyed a playing tile's
  player** when the composer mounted that tile's source a second time. The
  original tile now keeps its player and a duplicate tile gets its own play
  state.
- **Creator Edition routes fell under the 12px text floor and the 28px hit
  target.** The root font size is 14px, so `0.75rem` rendered at 10.5px; the
  pipelines, plugins, archive and dataviz styles now use the existing
  `--text-xs` token, and their small controls meet the 28px floor. Two
  unlabelled selects in the pipeline stage editor now carry accessible names.
- **The PVR recording-info modal requested the Creator-only plugin list** on
  every open, a guaranteed 404 in a PVR build. The method now lives in a
  creator module as `API.pluginList` and the modal calls it behind a `typeof`
  guard.
- **VOD downloads bypassed the concurrent-recording cap.** A 20-item
  back-catalogue pull forked 20 yt-dlp processes. The cap now applies on the
  `DownloadVod` path (0 = unlimited; finished and failed jobs hold no slot), a
  refusal names the post it refused, and a VOD pull honours the channel's
  capture profile instead of falling through to the global selector.
- **Render scratch collided across attempts and outputs were overwritable.**
  Two renders of one revision shared a scratch directory (the second's files
  deleted by the first's cleanup, five times out of five) and wrote the same
  `<recording_id>.mkv`. Scratch and output are keyed by a per-attempt id, an
  existing destination is refused before ffmpeg runs, and an artifact gate
  rejects a success with no file behind it. Creator Edition.
- **Security: media inputs are validated at the render execution boundary.**
  `editor_save` accepted client-named cut paths and times that the next render
  handed to ffmpeg. A server-side admission gate with stable `media-input/*`
  codes now runs at save, render and clipper-extract before any child process
  exists. Creator Edition.
- **Four Creator routes had no entitlement gate**, including
  `recording_captions`, which served a paid plugin's transcript store to
  unentitled callers with a 404 that read as "no transcript". The DataViz
  client called a route that has never existed behind `.catch(() => null)`, so
  a missing route, a refusal and "never transcribed" were one value; it now
  reads the real route and separates 404 / 402 / fault, and the chart panel
  carries idle / chart / skipped / refused / failed states. `end_sec` is
  `Option<f64>`, so a measured zero-length segment is no longer inflated to one
  second of speech nobody spoke.
- **The Pro entitlement set was decorative.** Nothing asserted the
  `pro_slugs()` derivation and the gate consulted only the debug override. An
  integration test now asserts both enforcement directions and that gate sites
  exist, and was proven non-vacuous by mutation.
- **Effects that rendered wrong or not at all**, found by decoding artifacts
  rather than checking exit codes: `strivo-pitch` emitted `formants=preserved`
  and rubberband spells it `formant`, so the setting had never applied;
  `volume=-inf` is an unrenderable file, not a mute (now `volume=0`);
  `asendcmd` curves were joined with `|` instead of `;` and delivered
  non-deterministically across threads, so ducking is now one `volume`
  expression over `t`; `SidechainKnobs` had no serde defaults.
- **Research schema and store defects.** `schema::rollback` never moved the
  version line, so a 2 -> 1 rollback left a database claiming v2 with v1
  tables. `schema::migrate` read the version outside its transaction and raced
  on `ALTER TABLE`. `Store::open` set `busy_timeout` after the statement it was
  meant to protect. Rebuilding `creator_metric_observations` silently dropped
  the live-status trigger; it is re-declared. Reading a package or posting read
  `project_id` out of the `id` column.
- **Creator job code that had been written but never compiled**:
  `recover_jobs` returned zero, the 19-edge transition table had no caller,
  `attempt_dir` omitted the job id its own doc claimed, an unknown state read
  as pending, and a cited edition test did not exist. Separately, the
  graph-to-run integration test had never run (four type errors in the caption
  export route hid it); compiling it exposed a wrong route, unregistered plugin
  names, an unreachable fake daemon and a JSON reader that read tagged enums
  as strings.
- **The research millisecond anti-drift check walked the source tree from
  inside a test** and failed with ENOENT under `cargo test --workspace` while
  passing per crate. It is now a build-script check that names file:line.
- **Accessibility.** `role="button"` on every sortable `<th>` made `aria-sort`
  invalid on all five; sorting destroyed focus so a table could be sorted
  once; the add-channel dialog never moved focus into itself; the Layout menu
  had no Escape; command-palette results were unlabelled click-only divs;
  pipeline run transitions had no live region. Seven critical and one serious
  axe violation, all closed. Timeline notices are patched rather than
  recreated so assistive tech sees a change instead of a fresh empty node.
- **`check-css-tokens.mjs` counted token-derived `color-mix()` as
  hardcoded**, inflating the census by 26 (PVR) and 37 (Creator).
- **`scripts/check-plan-deps.mjs` treated a ticked todo as absent.** Its parser
  matched only the unchecked checkbox, so ticking the first box of a wave
  removed that todo from the dependency DAG and the run reported 53 false
  invariant failures.
- **Documentation described systems that no longer exist.** `routes::recordings`
  was commented "retained but unmounted" while `server.rs` merges its router;
  the `strivo-web` README still advertised a TUI companion and an Askama/HTMX
  stack nothing loads; `licence-backend/README.md` cited a deploy workflow that
  does not exist. `src/edl/recorder.rs` existed only to snapshot the removed
  TUI's command log and is deleted.
- **Every generated crate README reported `Unit tests: 0`.** The generator
  anchored its test count on `^#\[test\]`, but every `#[test]` in the tree is
  indented inside `mod tests`, so all 34 counted zero. The same generator also
  hardcoded "a pure-data Rust crate — no IO, no DOM" prose that is false for
  crates such as `crates/editor` (SQLite + ffmpeg).

## [0.8.0] — 2026-09-20

### Added
- **Auto-download new uploads, Twitch/YouTube/Patreon, both editions.** A
  monitored Twitch/YouTube channel (livestream auto-record on) now also
  downloads its new uploads; the channel rail's right-click "Automatic
  downloads" section shows **Uploads** as "Included with Livestreams" for
  those, and as its own toggle for channels that aren't monitored (the new
  `auto_download_uploads` config list — extra channels beyond the monitored
  ones). Patreon reuses the existing `auto_pull_creators` list. The channel
  detail's Recent uploads header shows the same state. The monitor checks
  eligible channels for new uploads on their own 15-minute cadence (separate
  from the ~90s live-status poll, to avoid multiplying API cost), persists a
  per-channel watermark (the newest publish time seen) so a channel's first
  check never triggers a back-catalog download, dedupes against the
  recordings catalog, in-flight downloads, and its own just-enqueued pulls
  (repeated WebSub pushes can't double-download), and skips a channel's
  past-broadcast VOD only when a live capture of that broadcast actually
  exists. Each check logs a one-line summary at info level. New route:
  `PUT /api/v1/channels/{key}/auto_download_uploads`.
- **Dedicated recording player route (`#/play?recording=<id>`).** Opening a
  recording no longer lands on the live multiview wall (`#/watch`) with its
  chat rail, composer, and preset toolbar along for no reason — it opens a
  focused single-tile player instead. Recordings can still be placed as
  tiles on the wall through the composer or drag-and-drop; old
  `#/watch?recording=…&fresh=1` links (bookmarks, external callers) redirect
  to the new route automatically.

### Changed
- **The `#/watch` chat rail only appears when a live, chat-capable tile is
  actually on the wall.** A recordings-only (or empty) layout hides the rail
  entirely instead of reserving a dead collapsed-rail gutter; the persisted
  open/closed preference is unaffected once a live Twitch tile appears.
- **Recent uploads and Patreon post rows never link out to the source
  platform.** A row is inert until a matching finished download exists, at
  which point it opens the in-app recording player — the same rule already
  applied to Past Broadcasts.
- **Recordings carry `video_codec` / `audio_codec`** (ffprobe `codec_name`,
  probed when a recording finishes) on `GET /api/v1/recordings` and
  `/recordings/{id}`, and a finished recording's `duration_secs` is now the
  media's real duration rather than the job's wall-clock run time.
- **Channel rail rows and Home's Live Now cards are no longer links**, so
  hovering one no longer paints its URL in the browser's status bar. They
  stay keyboard-reachable (`role="link"`, Enter/Space) and draggable.

### Fixed
- **The recording player (`#/play`) opened muted at volume 0.** It inherited
  the multiview wall's "silent until raised" tile rule; it now starts audible
  at the last recording-player volume (a saved per-recording volume still
  wins). Wall tiles still start silent. When the browser refuses unmuted
  autoplay (a fresh load straight onto `#/play`), the tile shows a "▶ Play"
  button instead of a frozen first frame.
- **A recording that loaded but never decoded a frame sat on a black screen
  with no feedback.** An 8-second stall watchdog now shows the "Can't play
  this recording" overlay — with the file's codecs and whether this browser
  supports them, plus Retry / Download file / Copy file path — while
  ordinary buffering (data still arriving) is left alone.
- **VOD download progress went backwards and froze during the merge.**
  yt-dlp fetches video then audio and restarts its percentage per format;
  progress is now one overall, monotonic figure, a new `download_phase`
  (`downloading` / `merging`) drives a "Merging…" label, and
  `bytes_written` reflects the partial files on disk instead of 0 until the
  merge finished.
- **Manual VOD downloads recorded an empty `channel_id`** and could start a
  second yt-dlp for a URL already downloading; the SPA now sends the
  channel id and the daemon ignores a duplicate in-flight request.
- **The channel context menu read every channel as unmonitored** — it
  called `.find()` on the `{channels: […]}` response wrapper instead of its
  array.
- **Channel rail context menu: "Download uploads" was Creator-only and
  mislabeled.** The PVR build showed a permanently-disabled "(Creator)"
  button, and the Creator build's control was actually the archiver
  back-catalog tandem, not "download new uploads" — both toggles now do
  what they say (see the Added entry above), and every toggle in this menu
  (alerts, livestreams, uploads, and — Creator only — back-catalog
  archiving) rolls back its checkbox and shows an error toast if the
  underlying request fails, instead of showing a checked state the server
  never actually saved.
- **Per-channel toggles did nothing until the daemon restarted.** The channel
  and Patreon monitors held the `config.toml` snapshot from startup forever,
  so toggling a channel's livestream auto-record (and Patreon auto-pull) from
  the web UI was saved but ignored by the running daemon. Both monitors now
  re-read the config at the start of every poll, and the toggle routes
  trigger an immediate poll, so changes apply within seconds.
- **Ultrawide fullscreen centering for recording playback.** A recording's
  `<video>` tile kept its natural width and pinned to the left edge in
  fullscreen instead of centering with letterboxing; it now centers with
  `object-fit: contain` like every other tile kind.

## [0.7.0] — 2026-09-11

### Added
- **Platform auth failures are surfaced instead of silently degrading.**
  A rejected OAuth refresh (revoked/expired refresh token, bad app
  credentials) is now told apart from a transient network blip or rate
  limit, per RFC 6749 §5.2 — only a genuine rejection triggers a
  device-code re-login; a network hiccup no longer does. YouTube and
  Patreon report a rejected refresh the same way Twitch already did.
  The reason and how long it's been broken flow through the IPC snapshot
  as a per-platform `auth_issue` and show up in three places: the header
  health pill and System page (`/api/v1/health/checks` now says
  "credentials rejected — <reason>" with a Re-authenticate link, instead
  of a blanket "configured but not authenticated" that used to point at
  the since-removed TUI login), `strivo status` (one line per configured
  platform: authenticated, waiting for a device code, or "NEEDS
  ATTENTION" with the reason and a next step), and the SSE event stream
  (the header pill updates live, no reload needed).
- **Cookie-jar rejection detection.** `strivo setup cookies` imports a
  browser session for YouTube/Patreon, but nothing previously noticed
  when that session went stale. yt-dlp's stderr is now checked for the
  phrases it uses when a session is no longer accepted (bot/age
  challenge, members-only, expired cookies, sign-in/login
  required); a match surfaces a separate "cookie session rejected" issue
  with the `strivo setup cookies <platform> --browser <browser>` fix, and
  clears itself the next time a recording on that platform actually
  writes data.
- **Native installers.** A Linux AppImage plus a curl-pipeable terminal
  installer (`get-strivo.sh`), a Windows Inno Setup wizard installer, and
  a Docker image/compose stack — three additional install paths beyond
  building from source, all bundling ffmpeg/mpv/streamlink/yt-dlp so
  nothing has to be installed separately. Bundled tools are resolved next
  to the running executable before falling back to `PATH`.
- `strivo enable`/`disable` now support macOS via a generated `launchd`
  LaunchAgent, alongside the existing systemd (Linux) and Task Scheduler
  (Windows) paths. Windows builds also carry an embedded icon and
  version-info resource.
- **Player and watch page.** A capability-aware player controller
  interface, per-tile volume mixing, a unified tile chrome/player bar, and
  a compact docked bar for short grid tiles; multi-view gained a
  drag-and-drop layout composer with keyboard support and a channel
  picker card.
- **Design system.** Spacing/control/type tokens; the two Ctrl+K command
  palettes were merged into one; per-channel live/upload alert overrides;
  a right-click context menu for channels and stream tiles.
- Server-side validation for recording settings, with matching errors
  surfaced in the Settings UI.
- Recordings library: durable-journal pagination, generation-aware
  caching, and a generation-tracked API response cache.

### Fixed

- **Recording pipeline.** Container/extension is now detected from what
  ffmpeg/yt-dlp actually produced instead of assumed from the filename
  template; recordings no longer get listed twice; a new recording
  settles before its first poll instead of briefly reporting broken; the
  default yt-dlp format selector changed to `bv*+ba/b` (a bare `best`
  silently failed on many streams); a VOD download retries against its
  own URL instead of re-resolving a live stream; channel-alias YouTube
  URLs are rejected before reaching `vod_download`.
- **Playback.** Past Broadcasts pills play in-app instead of opening
  YouTube; Twitch and YouTube tiles drive through their platform embed/
  IFrame player APIs instead of a generic iframe; a live-channel click is
  honoured, and a broken recording says so instead of failing silently.
- **Security.** Every mutating and read-sensitive web route now requires
  auth — pipeline-chain delete/save/list, licence status/activate/
  refresh/trial issuance, recording download/play, Twitch chat routes —
  instead of trusting an unauthenticated request; session cookies use
  constant-time HMAC verification; auth now runs ahead of body/query
  extraction; vulnerable web and licence-backend dependencies (including
  two sharp/libheif CVEs) were updated.
- **Daemon.** Twitch EventSub follow listing and startup auth both retry
  instead of giving up on a transient network error; the `jobs.db` single
  mutex was replaced with a connection pool that recovers a poisoned
  connection instead of spinning; the daemon no longer writes a systemd
  unit on macOS.
- **Accessibility.** Recordings table headers are keyboard-sortable, a
  skip-to-content link was added, and sub-12px text across the rail,
  table, schedule, and general chrome was raised to the design system's
  minimum sizes.
- Twitch readiness now waits for the user id to resolve before reporting
  ready; YouTube live detection no longer depends on live chat being
  present; YouTube streams no longer get routed into the Twitch player.
- **Release boundary.** Unreleased experimental content is now genuinely
  absent from the released PVR bundle and its `--help`/`doctor` output,
  not just hidden at runtime.

## [0.6.0] — 2026-08-18

### Added
- **Windows support.** StriVo builds and runs on Windows for the first time.
  The daemon and its clients talk over a named pipe (`\\.\pipe\strivo`)
  instead of a Unix socket, behind an `Endpoint`/`Listener`/`Stream`
  abstraction in `src/ipc.rs`; the newline-delimited JSON protocol is
  unchanged. Process liveness uses `OpenProcess`/`GetExitCodeProcess`, the
  disk-budget gate and storage gauge use `GetDiskFreeSpaceExW` (both were
  silently disabled on Windows), mpv playback uses a named pipe, and
  `strivo enable` installs a Task Scheduler logon task. Verified on a real
  MSVC build: the daemon runs headless, the web UI serves, and a stopped
  recording is finalised. CI cross-checks the Windows target on every push.
- **Coding Studio.** The research kernel's API was complete but almost
  entirely unreachable — the interface exposed 8 of 15 routes and none of the
  codebook. Adds Codebook (hierarchical codes, codings, apply-coding), Corpus
  (sources, cases, signal browser), and Notebook (memos, relationships,
  agreement, export) surfaces, plus the nine read routes they need.
- **Inter-coder reliability.** Cohen's kappa over two coders' codings
  (`crates/research/src/agreement.rs`), with observed and expected agreement.
- **REFI-QDA export.** Project export in the Rotterdam Exchange Format
  (`crates/research/src/refi.rs`), so a corpus can move to NVivo, ATLAS.ti, or
  MAXQDA. Built against the published v1.5 standard.
- `scripts/check-windows.sh` — cross-checks the Windows target from Linux.

### Fixed
- **Recordings stopped on Windows are no longer truncated.** ffmpeg only
  writes the Matroska trailer on a graceful shutdown; the Windows path
  hard-killed it, producing files that played but had no duration and could
  not seek. ffmpeg now receives `q` on stdin — which needs no console, so it
  works from a headless daemon — with a console-attach `CTRL_BREAK` fallback
  for yt-dlp. Covered by `tests/graceful_stop.rs` on both platforms.
- **Project export no longer fails past 1,000 signals.** `export_project`
  returned a validation error rather than paginating, so any archive more than
  a few weeks old could not be exported at all.
- **All research routes require the Pro entitlement.** 13 of 15 checked only
  authentication, so an authenticated client could create codes, codings, and
  memos and trigger migrations without a licence. **Breaking** for any API-key
  client relying on the old behaviour.
- The daemon no longer reports every external tool as missing on Windows: it
  shelled out to the `which` binary, which does not exist there.
- `strivo doctor` gives platform-appropriate install advice instead of always
  suggesting `pacman`, and now checks `ffprobe`, which the multitrack path
  requires.
- The daemon shuts down gracefully on Windows (`CTRL_CLOSE`/`CTRL_SHUTDOWN`);
  it previously had no graceful path there at all.
- The release workflow can be rehearsed via `workflow_dispatch` without
  burning a tag, and every build job is time-bounded — a prior release sat on
  an offline runner for 24 hours. Linux and macOS artifacts verified
  end-to-end.
- CI is green again after three weeks red: Node is pinned rather than
  inherited from the runner, and the end-to-end lockfile is tracked instead of
  gitignored while `npm ci` required it.
- Every public URL pointed at a GitHub org that does not resolve.

### Added — Creator Edition (CE-Fusion wave)
- **CE-Fusion wave (NVivo-meets-Riverside bridge).** Strategy recorded in
  `docs/STRATEGY-NVIVO-RIVERSIDE.md`; roadmap section `CE-Fusion` in
  `ROADMAP.md`.
  - **Archive search** (`crates/research/src/search.rs`): FTS5 lexical search
    over `transcript.utterance` signals; phrase-quoted queries, deterministic
    `(source_id, start_ms, id)` ordering, bounded pagination, cross-project
    isolation. `GET /api/v1/research/projects/{id}/search`.
  - **Moments projection** (`crates/research/src/moments.rs`): codings and
    clip-worthy detections (`visual.scene_change`, `audience.anomaly`) merged
    into one creator-vocabulary stream; creating a moment writes a real
    human-origin coding through existing kernel validation. GET/POST
    `/api/v1/research/projects/{id}/moments`.
  - **Content-free product telemetry** (`crates/strivo-web/src/telemetry.rs`):
    per-route latency/reliability aggregation (matched route template + status
    + duration only, both editions, local-only). Authed `GET /api/v1/telemetry`.
  - **SPA Archive surface** (`#/archive`, creator-gated): workspace bootstrap,
    index-my-archive (migration reports), debounced paginated transcript
    search, moments list/create with origin badges and min-confidence filter,
    and "Open in Editor" deep links that open the EDL editor at the hit's
    timecode.
- **Phase 0 experience audit** at
  `docs/audits/PHASE0-EXPERIENCE-AUDIT-2026-07-30.md` — 33 evidence-cited
  findings across UX journeys, PVR and Creator performance.
- **Webhook notification settings UI**: enable toggle + validated URL field on
  the Settings pane; `POST /api/v1/settings/update` now accepts
  `notifications.webhook.enabled`/`.url` (http/https validated, empty clears).

### Fixed
- Nine Creator handlers (editor render, clip extract, thumbnails, reuse,
  casebook, heatmap, cuepoints, clipper analyze, editor load) no longer run
  ffmpeg/ffprobe synchronously on Tokio worker threads — moved onto
  `spawn_blocking` with identical wire contracts (audit F-32).
- Pipeline resource-lock acquisition is bounded (600 s timeout → existing

- Licence trial/activate controls are disabled with an explanation when the
  backend reports `implemented:false` instead of failing on click (audit F-11).
- `ui.reduce_motion` is actually wired: root class driven by the setting OR

  covers the REC-dot and state-pill pulse animations (audit F-18).
- `CREATOR_ENABLED` is re-resolved after login, so creator routes (including
  Archive) appear on a fresh session without a manual reload.

- Esc precedence: clear filter first, then navigate back. Status indicator

# Media fixture corpus

The representative, redistributable media corpus for the Creator work
(report item F10, plan todo 32). Eight classes, 702 KB total, every file
generated by ffmpeg from a `lavfi` synthetic source. There is no input file,
no downloaded media and no capture of anything a person made.

It lives here rather than under `crates/strivo-web/assets/` on purpose: that
tree is copied wholesale into `$OUT_DIR` and embedded into every PVR binary
(`crates/strivo-web/build.rs`), so a fixture vendored there would ship inside
the released product.

## Use it

```js
import { fixture, byClass, integrity } from "../../../fixtures/media/fixtures.mjs";

const silent = fixture("silent-video.mkv");
silent.class;        // "silent-video"  — a claim
silent.ffprobe;      // ffprobe's reading — the evidence for the claim
```

Rust lanes read `MANIFEST.json` directly; it is the cross-language contract,
and `fixtures.mjs` is the JS-side convenience over it rather than a second
source of truth.

## Regenerate and verify

```sh
scripts/seed_media_fixtures.py          # rewrite the corpus
scripts/verify_media_fixtures.py        # prove what each file actually is
scripts/verify_media_fixtures.py --quick   # skip the regeneration comparison
```

The seeder takes about 1.5 s and produces byte-identical output for a given
ffmpeg build (`-fflags +bitexact` keeps the Matroska muxer's `DateUTC` and
random `SegmentUID` out of the files). The verifier is the part that matters:
it re-probes every file, checks the manifest against the bytes on disk, and
fails on a class that is not really there.

## The classes

| Fixture | Class | What ffprobe reports |
| --- | --- | --- |
| `multi-audio.mkv` | multi-audio | 1 video (h264), 2 audio: aac/2ch and opus/1ch |
| `silent-video.mkv` | silent video | 1 video (h264), 0 audio |
| `variable-frame-rate.mkv` | variable frame rate | 15 frames, presentation deltas 40 ms x10 and 120 ms x4 |
| `mixed-codecs.mkv` | mixed codecs | mpeg4 video, mp3 audio |
| `long-gop.mkv` | long GOP | 100 frames, exactly 1 keyframe |
| `unicode-path/日本語 セッション 🎬 2026-09-26.mkv` | Unicode path | h264 + aac, stored under a non-ASCII path |
| `discontinuities.mkv` | discontinuities | 30 frames, one 1.04 s presentation-time jump at frame 15, keyframe on the far side |
| `landmarks.mkv` | landmarks | 200 frames, luma step per second; 1 kHz beep in the first 50 ms of each second |

`landmarks.mkv` is the one a timing assertion should use: second *k* is a flat
luma value that steps by exactly 28 from the second before it, and carries a
1 kHz tone in `[k, k+0.05)` with exact digital silence for the rest of that
second. Both are asserted on decoded samples, not on container metadata.

## Licence

Every fixture is the output of ffmpeg applied to a source ffmpeg generated, so
no third-party rights attach to any of them; they ship under this repository's
MIT licence (`LICENSE`) alongside the script that produced them. The basis is
recorded per fixture in `MANIFEST.json`, not just here, so a reader auditing
one file does not have to trust its name to find the answer.

No fixture contains personal data. The `unicode-path` class deliberately
contains non-ASCII *bytes in a path* and nothing else.

## Reproducibility caveat

Byte-identity holds for a **given ffmpeg build**. A different ffmpeg may pick
different rate-control defaults, which is why the verifier's load-bearing
regeneration assertion compares ffprobe-reported properties and reports
byte-identity alongside it rather than depending on it alone.
